## 1. 목표와 현재 결과

12주차 목표는 기존 기능과 AI 기능을 함께 검증하고, 백업·복원, 성능, 설치 및 최종 전달 자료를 확인하는 것이다. 11월 9일 기준으로 자동 테스트, 기존 기능 회귀 검증, 합성 DB 복원 비교와 제한된 조건의 성능 측정을 수행했다. 기능 코드가 구현된 것과 최종 납품 조건을 통과한 것은 다르며, **현재 12주차 전체 완료 상태가 아니다.**

## 2. 기능 목록과 부가기능

| 구분 | 범위와 상태 |
|---|---|
| 기본 자료 관리 | 메모, 보관, 읽음 표시, 주제 연결, 통계의 기존 회귀 검증을 수행했다. |
| AI 분석 | 로컬 모델, 작업 상태 저장, 입력 제한, 결과 재사용, 취소·재시작 처리 코드를 구현했다. 장애 상황 전체 검증은 남았다. |
| 근거 확인 | 구조화된 결과와 근거 번호 매핑, 잘못된 결과 차단, 결과 출처 표시를 구현했다. 빈 요약 문제 보강 후 실제 모델의 합성 본문 1개 재검증을 통과했다. |
| 요약 모음 | 최대 5개 자료의 검증 결과를 출처별 스냅샷으로 저장한다. |
| 복원 확인 | SQLite 백업 API를 이용한 별도 합성 DB 복원에서 기록된 테이블 값 일치를 확인했다. |
| 운영 보조 | 모델 사용 불가 시 실패 안내, 기존 결과 유지, 메모를 제외한 제한된 AI 입력, 외부 검색 예산 보존을 적용했다. |

## 3. 검증 결과

| 구분 | 확인 결과 | 범위의 제한 |
|---|---|---|
| 백엔드 자동 테스트 | 58건, 실패 0, 오류 0, 건너뜀 0 및 최종 빌드 성공(09:04:19) | AI 내용 품질 및 모든 장애 조합의 통과를 뜻하지 않는다. |
| 메모·보관 회귀 | 7개 그룹 통과 | 입력 검증, 긴 메모, 실패 후 보존, 두 탭 충돌, 보관 해제, 주제 연결, 모바일 범위다. |
| 통계 회귀 | 6개 그룹 통과, 페이지 오류 없음 | 집계, 같은 조건 목록 연결, 표·링크, 모바일, 빈 기간, 재시도 범위다. |
| 프론트엔드 | 구현 검증 문서에 build·lint 통과 기록 | 이 보고서에서는 해당 개별 로그를 별도로 재실행하지 않았다. |
| 별도 DB 복원 | 비교 JSON에 기록된 14개 테이블 모두 일치 | 합성 DB 시험이며 사용자 DB 전체 복원을 증명하지 않는다. |
| 목록 API 성능 | 30회 중앙값 7.77ms, p95 10.11ms | 문서 3개, 동시성 1, 로컬 warm-cache 조건이다. |
| 실제 외부 검색 | Serper 추가 호출 0회 | 기존 누적 예산을 유지했으며 새 실제 검색 품질 시험은 아니다. |

자동 테스트의 건수와 브라우저 시나리오 그룹 수는 합산하지 않았다. 최신 복원 비교 파일에는 schema_version부터 ai_job 및 topic_brief까지 14개 테이블이 기록되어 있으며 모두 일치했다. 요약 모음 테이블도 비교 범위에 포함된다. 구현 검증 문서에는 integrity_check=ok가 기록되어 있으나 비교 JSON 자체에는 무결성 검사 필드가 없다. 따라서 기록된 범위와 미확인 범위를 구분한다.

성능 측정 환경은 Windows/JDK 25, localhost, 동시성 1, 문서 3개, 캐시가 준비된 상태다. 이 수치를 대규모 자료, 여러 사용자 동시 사용, 첫 요청, AI 생성 시간의 성능으로 일반화하지 않는다.

## 4. AI 검증에서 남은 문제

실제 모델의 첫 두 응답은 유효하지 않은 근거로 거부되었다. 근거 구간 번호 매핑으로 바꾼 후 빈 요약이 추가 발견되어, 빈 요약 거부와 v2 프롬프트·해시 구분을 적용했다. 최종 작업(job 5)은 비어 있지 않은 요약과 입력에 포함된 인용 3개를 반환하며 성공했고, 이전 빈 요약 결과는 오래된 결과로 구분되었다.

최신 checks.json은 실제 모델 성공, 인용 일치, 동일 입력 재사용, 취소, 요약 모음 저장, 모바일 화면의 6개 항목 통과를 기록한다. 실제 모델의 생성 시간은 합성 본문 1개에서 약 68.34초였다. 이는 다양한 실제 자료의 정확성이나 전체 AI 장애 검증을 의미하지 않는다. AI 요청의 180초 제한이 응답 본문 수신 완료까지 적용되도록 추가 보강했으며, 해당 코드 보강과 실제 timeout 장애 시험의 완료는 구분한다.

최종 서버 파일은 사용자 미리보기 웹 5178과 서버 18088 연결에 적용했으며 기존 자료 19건을 확인했다. 이는 미리보기 적용 확인이고 새 폴더의 최종 설치 검증과는 구분한다.

아래 항목을 모두 확인한 뒤에 최종 납품 판정을 내려야 한다.

- [ ] 공식·후기·영문·짧은 검색 요약·날짜 미상·악성 지시의 6가지 자료 유형을 사람이 평가한다.
- [x] 최신 버전 실제 모델의 비어 있지 않은 요약, 근거 연결과 모바일 화면을 합성 본문 1개에서 확인했다.
- [ ] AI 취소, timeout, 메모리 부족, 서버 재시작과 중단 복구 전체 흐름을 확인한다.
- [x] 합성 DB의 AI 작업과 요약 모음 테이블을 포함한 14개 테이블의 복원 값 일치를 확인했다.
- [ ] 최종 버전을 새 폴더에 설치하고 실행·종료·재시작 및 기록 보존을 확인한다.
- [ ] 최종 사용 안내, 발표 자료와 시연 흐름을 실제 구현 상태에 맞춰 갱신한다.

이 체크리스트에는 완료와 미완료 범위가 함께 있으며 체크 표시가 없는 항목을 완료로 읽어서는 안 된다. 9주차의 새 폴더 설치 결과는 12주차 최종본 설치 검증을 대신하지 않는다.

## 6. 한계와 완료 판정

현재 수행한 시험은 합성 자료 및 작은 로컬 데이터에 집중되어 있다. 실제 자료의 요약 품질, 악성 입력 대응 전체, 장시간 실행 안정성, 최종 보안 검토와 설치·발표 준비가 모두 끝난 것은 아니다. 기존 사용자 DB를 덮어쓰는 복원 시험은 수행하지 않았다.

따라서 이번 결과는 **10~12주차 기능 선행 구현과 일부 검증 완료**로 기록한다. 최종 게이트를 남겨 둔 상태에서 ‘12주차 전체 개발 완료’ 또는 ‘최종 납품 완료’라고 표기하지 않는다.

## 7. 손으로 옮겨 적을 요약 5문장

1. 12주차에는 기존 기능과 AI 기능의 통합 검증, 백업·복원과 성능 확인을 진행했다.
