## 완료 기준과 결과

6주차의 저장 자료 목록·필터·상세 화면에 사용자 기록 기능을 연결했다. 읽기 상태, 보관, 즐겨찾기, 나중에 읽기와 메모를 저장하고, 보관함에서 조건별로 자료를 찾아 상세 화면을 오갈 수 있다. 계획 문서 사이에 보관함 배정 주차가 달라 단계별 개발 가이드의 7주차 기준으로 포함했다. 통계와 작업 이력은 8주차 범위이며, 이번 완료 판정은 전체 프로젝트가 아닌 위 7주차 정의 범위에 한정한다.

구현 계약은 [7주차 사용자 기록 계약](week7-contract.md), 검증 근거는 [7주차 구현·검증 기록](week7-verification.md)과 개발 담당자의 최종 검증 결과다. 보고서 작성 단계에서는 시험을 재실행하지 않았다.

## 구현한 내용

읽기 상태는 기본 미읽음(UNREAD), 읽는 중(READING), 읽음(READ)으로 구분한다. 보관·즐겨찾기·나중에 읽기는 각각 독립된 값이며, 자료를 열거나 즐겨찾기하는 동작으로 읽기 상태를 자동 변경하지 않는다. 상태 API는 전달한 필드만 변경하고, 화면은 서버 저장 성공 후 갱신한다. 요청 중에는 조작을 잠그고 실패 시 기존 상태와 재시도 경로를 유지한다.

메모는 최대 20,000 UTF-16 코드 단위의 일반 텍스트로 저장하며 공백과 줄바꿈을 보존한다. HTML 문자열은 실행하지 않는다. 저장 버튼으로 명시적으로 저장하고, 서버 조회값과 편집 중 초안을 분리하여 재조회나 저장 실패가 입력을 덮지 않도록 했다. 저장 중에는 편집을 잠근다. 자동 저장은 구현하지 않았다.

메모에는 버전을 부여하여 오래된 버전의 저장 요청을 409 충돌로 처리한다. 충돌 화면에서 서버 메모와 내 입력을 비교한 뒤 사용자가 직접 내 입력 저장 또는 서버 메모 사용을 선택한다. 최초 저장의 동시 경쟁도 조건부 저장으로 보호한다. 문서별 미저장 초안과 기준 버전은 sessionStorage에 임시 보관하여 같은 탭에서 이동·새로고침 후 복원한다. 이는 서버 영구 저장과 구분되며 탭 종료 뒤 복구를 보장하지 않는다.

보관함은 보관한 자료만 조회하며 읽기 상태·즐겨찾기·나중에 읽기·주제와 기존 제목·출처·기간·정렬·페이지 조건을 지원한다. 상세 화면을 왕복해도 목록 조건을 유지한다. 보관을 해제하면 보관함에서만 사라지고 원문·메모·다른 사용자 상태는 유지된다.

문서에 여러 주제를 연결하거나 연결만 해제할 수 있다. 연결 해제는 문서를 삭제하지 않으며 재수집이 명시적으로 해제한 연결을 자동 복원하지 않는다. 기존 검색 이력의 주제는 유지하고, 기존 문서 재수집으로 사용자 상태나 메모를 덮어쓰지 않도록 했다.

백엔드 시험은 독립 상태와 부분 변경, 필터, 긴 메모와 줄바꿈, 재수집·DB 재열기, 오래된 버전과 빈 메모, 최초 저장 동시 경쟁, 주제 해제 후 재수집, 잘못된 입력·없는 문서, DB 쓰기 실패 롤백을 포함한다.

브라우저에서는 잘못된 입력의 400·없는 문서의 404·메모 충돌의 409 응답, 긴 메모와 HTML 문자열의 저장·새로고침 보존 및 스크립트 미실행을 확인했다. 메모 저장에 500 응답을 주입했을 때 입력과 서버 기존 내용이 유지되고, 새로고침 뒤 초안 복원과 재시도가 성공했다. 두 탭의 충돌 비교·명시적 저장, 보관함 필터와 상세 왕복 조건 복원, 보관 해제 및 주제 연결·해제 후 기록 보존도 통과했다.

390px 상세 화면에서 가로 넘침이 없었고 브라우저 런타임 오류도 없었다. 이는 전체 기기 호환성이나 접근성 감사 결과는 아니다. 초기 브라우저 시험의 체크박스 대기 방식은 서버 성공 후 갱신하는 계약에 맞게 수정했으며 최종 재실행은 통과했다. 근거 자료는 `output/week7-tests/results.json`과 실패·충돌·보관함·모바일 상세 화면 이미지다.

원본 schema 3 DB를 SQLite backup API로 일관되게 복사한 뒤 복사본에 schema 4·5를 순차 적용했다. 기존 열의 행 수와 SHA-256 지문을 비교하여 topic 1건, search_run 2건, search_hit 17건, document 17건, provider_budget 1건이 모두 동일함을 확인했다. 복사본의 무결성 검사 결과는 `ok`다. 원본 DB와 사용자 서버는 변경하지 않았고 신규 Serper 호출도 없었다.

미리보기 `http://127.0.0.1:5178/documents`와 `/library`는 18088 서버 및 `output/week7-preview.db` 복사본에 연결된다. 이 화면에서 새로 저장한 사용자 기록도 복사본에 남으며 원본 DB로 자동 반영되지 않는다. 따라서 이번 결과는 구현·격리 검증·복사본 미리보기 완료이며 원본 서버 적용 완료를 뜻하지 않는다. 실제 본문 확보 성과도 이번 작업으로 변경되지 않았다.

## 용지에 적을 요약

7주차에는 읽기 상태·보관·즐겨찾기·나중에 읽기를 독립적으로 저장하고 보관함에서 필터와 상세 화면 이동을 사용할 수 있도록 구현했다. 일반 텍스트 메모의 수동 저장, 실패 시 입력 보존, 같은 탭의 초안 복원과 버전 충돌 시 사용자 선택 기능을 완성했다. 복수 주제 연결·해제와 재수집 과정에서도 문서와 사용자 기록을 유지하도록 했다. 백엔드 최종 45건과 프런트엔드 build·lint, Playwright 7개 검증 그룹을 통과했고 실제 Java 서버 재시작 뒤 메모와 읽기 상태의 정확한 일치를 확인했다. 기존 자료의 복사본을 업그레이드하여 행 수·지문·무결성을 확인했으며 원본 DB와 사용자 서버는 변경하지 않았고 새 Serper 호출도 없었다. 완료 판정은 단계별 가이드의 7주차 범위에 한정하며 통계·작업 이력, AI 분석과 자동 메모 저장은 후속 과제로 남아 있다.
