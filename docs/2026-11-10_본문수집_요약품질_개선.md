# 본문 수집 및 로컬 AI 요약 개선 검증

## 원인

사용자가 제보한 자료(문서 32)는 본문 수집 정책이 미등록되어 `POLICY_NOT_APPROVED` 상태였다. 이는 HTTP 다운로드 실패가 아니라 다운로드 전 차단 상태였다. 저장된 검색 제공자 발췌문은 85자로, 기존 AI 요약은 이 발췌문만 입력받아 한 문장을 반복하는 수준이었다. 발췌문 끝의 `...`도 제공자가 전달한 내용에 포함되어 있었다.

## 수정

- 사용자가 지정한 공개 페이지 `https://erulabo.com/384`만 검토 규칙에 등록했다. 도메인 전체를 허용하지 않으며 기존 사용자 에이전트와 접근 제한을 유지한다. 로봇 정책 확인은 저작권 재배포 허가를 의미하지 않는다.
- 본문 가져오기 API와 명시적 버튼을 추가했다. 검토하지 않은 출처에는 버튼을 제공하지 않는다. 중복 클릭을 막고, 본문 수집 중에는 AI 요청을 잠근다.
- 실제 본문 10,268자를 확보했다. 검색 발췌문·제목·URL은 보존했다. 본문 탭에서는 받은 내용을 스크롤하여 끝까지 확인할 수 있다.
- 긴 본문의 앞·중간·끝에서 실제 문자열 구간을 최대 10개 선별한다. 모델 입력은 최대 1,200개 유니코드 문자로 제한하며, 전체 본문을 읽었다고 표시하지 않는다.
- 프롬프트 v6는 요약과 서로 다른 핵심 항목 3개를 요청한다. 각 항목에는 설명 대상을 포함하도록 한다. 긴 입력의 결과에는 요약 80자 이상, 서로 다른 주장 3개, 서로 다른 인용 구간 2개 이상이 필요하다. 근거 번호는 서버에서 실제 본문 문자열로 치환하고 일치를 검사한다. 이 검사는 주장의 의미적 정확성까지 보장하지 않는다.
- 문장 경계와 공백을 우선해 발췌하여 단어 중간에서 끊기는 문제를 줄였다. 공백 없이 이어진 한국어 문장과 유니코드 보조문자도 회귀 테스트에 포함했다.
- 기존 발췌문 요약을 이전 결과로 표시하고 재요약을 안내한다. 실패해도 이전 성공 결과를 지우지 않는다. 메모는 AI 입력에 포함하지 않는다.

## 확인한 결과

- 백엔드 테스트 85개 통과, 실패 및 오류 0개.
- 프런트엔드 빌드와 린트 통과.
- 본문 수집·요약 전환 화면 시나리오 6개와 기존 AI 오류·복구 시나리오 8개 통과. 화면 테스트의 AI 응답은 모의 데이터이며 실제 모델 검증과 구분한다.
- 메모, 읽기 상태, 검색 예산, 검색 결과 연결, 주제의 변경 전후 지문이 모두 일치했다.
- 이번 수정 검증에서 Serper 검색을 추가 호출하지 않았다. 기존 검색 서버와 키는 유지했다.
- 실제 본문 입력 v3와 v4는 각각 180초 제한에 걸렸다. 이 PC의 모델은 GPU 없이 CPU로 실행된다. v5부터 입력 1,200문자·생성 최대 650토큰·스레드 4개로 제한하고, 이 실행 환경의 대기 시간을 최대 300초로 설정했다.
- v5 실제 모델은 133.5초에 성공하여 세 문장과 근거 3개를 생성했으나, 사람이 읽었을 때 설명 대상이 불분명하고 인용이 중간에서 끊기는 문제가 남았다. 이를 성공 응답만으로 품질 완료로 간주하지 않고 v6에서 문장 처리와 프롬프트를 추가 수정했다.
- v6 실제 모델은 84.5초에 응답했고, 요약 3문장과 실제 본문에 포함되는 인용 3개를 저장했다. 문장 경계와 처리 시간은 개선됐다. 그러나 사람이 읽었을 때 소개글을 게임 자체와 혼동한 표현과 불완전한 핵심 문장이 남았다. 따라서 **본문 수집 복구와 실행 안정성은 확인했지만 요약 내용 품질은 완료 판정하지 않는다.** 설치된 `llama3.2:3b`의 실제 응답을 품질 기준으로 사용해야 하며 자동 테스트 통과를 내용 정확성 보장으로 해석하면 안 된다.

## 범위와 한계

다른 출처는 별도 검토가 필요하다. 로그인·유료·동적 페이지의 본문 확보를 보장하지 않는다. 긴 본문은 일부 구간을 선별하므로 상세 내용은 원문과 대조해야 한다. 이번 문서는 사용자 제보 수정의 검증 기록이며 전체 프로젝트의 모든 최종 검증 완료를 뜻하지 않는다.
