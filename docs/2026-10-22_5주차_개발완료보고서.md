## 완료 기준과 결과

같은 자료의 URL 변형을 보수적으로 식별하고, 재수집하더라도 기존 문서 ID와 검색별 기록을 보존하도록 구현했다. 확실한 URL 비교 키 일치와 검토가 필요한 중복 후보를 구분한다. 제목이나 본문이 같다는 이유만으로 다른 출처의 문서를 합치지 않으며, 기존 데이터에서 비교 키가 충돌해도 기존 ID와 참조를 유지한다.

UrlNormalizer·DocumentMatcher와 SQL 004를 추가했다. 문서 비교 키, 원래 URL 별칭, 매칭 근거, 규칙 버전, 중복 검토 후보를 별도로 저장한다. 합성 자료와 실제 자료는 식별 공간을 분리했다.

## 구현한 내용

URL 비교 규칙 버전은 `url-v1`이다. HTTP(S)의 scheme·host를 소문자로 바꾸고 기본 포트, fragment, 명시된 추적 파라미터를 제거한다. 빈 경로는 `/`로 처리한다. 반면 id·page·lang 같은 의미 있는 파라미터, 파라미터 순서·반복·원래 인코딩, 경로 대소문자와 마지막 slash는 보존한다. 서명·토큰 파라미터가 있으면 query 전체를 유지한다. 정규화할 수 없는 값은 원래 문자열을 키로 보존하여 다른 검색 결과까지 사라지지 않도록 했다. 비교 함수는 네트워크에 접근하지 않으며, 원문 접근 안전성 판단은 별도 기능이다.

`document_identity`의 비교 키와 합성 여부 조합을 유일하게 유지하고 짧은 쓰기 트랜잭션으로 재수집을 연결한다. 같은 검색 안의 동일 자료는 한 hit와 최초 순위·요약을 유지하며 URL 별칭은 남긴다. 서로 다른 검색의 순위와 검색 요약은 각각 보존한다.

구버전 문서의 비교 키가 충돌하면 `LEGACY_NORMALIZED_COLLISION` 검토 후보를 남긴다. 두 문서 ID와 기존 별칭 소유자를 바꾸지 않는다. 새 URL 변형은 비교 키의 최초 소유자에 연결하지만 기존 원래 URL은 기존 별칭 소유자를 유지한다. 구버전 `document.normalized_url`을 일괄 변경하지 않고 새 비교 기준은 identity·alias 테이블에서 관리한다.

canonical은 같은 비교 키인지, 다른 origin인지, 잘못된 홈 지정인지 등을 기록하는 힌트다. 자동 병합이나 추가 원문 요청에 사용하지 않는다. 비어 있지 않은 성공 본문의 SHA-256·해시 버전 일치, 또는 제목과 확인된 발행일 일치는 검토 후보로 기록한다. 빈 본문이나 날짜 미상인 같은 제목은 중복 근거로 사용하지 않는다. 후보 기록만으로 문서를 자동 삭제하지 않는다.

본문을 확보하지 못한 재수집은 기존 본문을 지우지 않는다. 기존 본문 해시가 바뀌면 `content_version`을 증가시킨다. 본문 해시 버전은 `jsoup-text-v1`이며 후속 AI 기능에서 변경 여부를 비교할 수 있는 기반만 마련했다. 현재 AI는 연결하지 않았다.

## 검증 결과

검증 수치는 [5·6주차 검증 기록](week5-6-verification.md)에 남긴 개발 담당자의 실행 결과를 근거로 한다. 보고서 작성 단계에서는 서버·시험·외부 요청을 다시 실행하지 않았다.

- 5주차 첫 회귀 자동시험 31건이 통과했다. 6주차와 추가 경계 시험을 포함한 최종 누적 백엔드 자동시험은 38건이며 실패·오류·건너뜀은 0건이다. 31건과 38건은 별도 합산 대상이 아니다.
- 최종 IdentityTest 9건은 추적 URL 변형, 의미 있는 query·서명 보존, canonical 비병합, 다른 출처, 빈 본문, 메타데이터 재수집, 동시 저장, 기존 ID 충돌, 정규화 불가 자료 처리를 확인한다. 자동시험은 임시 DB와 합성 자료를 사용했다.
- 외래키로 문서 ID를 참조하는 `user_note` 시험 테이블을 만들어 재수집 후 같은 ID와 메모 값이 남는지 확인했다. 이는 참조 보존 시험이며 사용자 메모 작성·수정 기능을 구현했다는 뜻이 아니다.
- 최종 Maven test·package, 프론트 TypeScript 타입 검사·Vite 빌드·ESLint가 통과했다. 이 결과는 실제 사이트의 본문 확보 성공률이나 대규모 성능 측정값이 아니다.

## 기존 실제 자료 보존 확인

기존 실제 검색 자료 17건을 담은 DB의 일관된 복사본에만 SQL 004와 identity·alias 보완을 적용하고 조회했다. 사용자 원본 서버와 원본 DB는 종료·수정하지 않았다. 원본 DB 업그레이드는 다음 정상 서버 재시작 시 적용된다.

업그레이드 전후 주제, 검색 hit, 검색 조건·요청키·시각, 원래 문서 URL·제목·합성 여부, 호출 예산 지문이 일치했고 `integrity_check=ok`였다. 기존 검색 1은 PARTIAL·7건·본문 제한 1건, 검색 2는 SUCCEEDED·10건을 유지했다. 공식 2건·사용자 3건·기타 12건과 BLOCKED 1건·METADATA_ONLY 16건도 그대로다. 이번 5·6주차 검증의 새 Serper 호출은 0회이며 누적 `attempts=2`를 유지했다.

실제 본문 확보는 기존과 동일하게 0건이다. 본문 파서 성공 경로와 본문 중복·변경 보존 검증은 합성 자료 시험이다. 실제 자료 17건을 다시 검색하거나 본문을 추가 확보한 것으로 표현하지 않는다.

## 주요 산출물과 한계

주요 산출물은 `UrlNormalizer.java`, `DocumentMatcher.java`, `004_document_identity.sql`, `IdentityTest.java`와 [문서 식별·보존 규칙](week5-identity-rules.md)이다. 6주차 목록·상세 수동 브라우저 검사는 별도 보고서에 기록하며 자동 E2E 시험으로 계산하지 않는다.

검토 후보의 수동 병합 UI, 읽기 상태·보관·메모 UI와 AI 분석은 구현하지 않았다. 읽기·메모·보관은 7주차 이후 범위다. 현재 식별 규칙은 보수적인 URL 비교와 후보 기록이므로 내용이 같은 모든 문서를 자동으로 찾아 합친다는 의미가 아니다.

## 용지에 적을 요약

URL 비교 규칙과 문서 식별 정보를 추가하여 같은 자료를 다시 수집해도 기존 문서 ID와 검색별 순위·요약을 보존하도록 구현했다. 확실하지 않은 중복과 기존 ID 충돌은 자동 병합하지 않고 검토 후보로 남겼다. 합성 자료로 본문·참조 기록 보존을 시험하고, 실제 자료 17건은 복사본 DB에서 업그레이드 후 보존을 확인했다. 새 외부 검색은 없으며 실제 본문 확보·메모 UI·AI 구현을 완료한 것은 아니다.
