# 9주차 개발 완료 보고서

- 프로젝트: 동양미래대학교 리서치 보드
- 작성일: 2026년 11월 9일
- 해당 주차: 9주차, 2026년 11월 9일~15일(9월 14일을 1주차 시작일로 가정)
- 완료 범위: AI를 제외한 핵심 이용 흐름의 통합 검증과 실패 복구 개선

## 1. 이번 주 목표와 완료 결과

이번 주 목표는 검색부터 출처 확인, 자료 보관, 메모 작성, 읽음 표시, 통계 확인까지 한 흐름으로 사용할 수 있는지 확인하는 것이었다. 저장이나 검색에 문제가 생겼을 때 사용자의 입력과 기존 기록을 유지하고, 서버를 종료했다가 다시 실행해도 기록을 불러오는지도 점검했다.

2026년 11월 9일 기준으로 9주차 계획 범위의 구현과 검증을 완료했다. AI가 꺼진 실제 로컬 서버에서 전체 흐름을 확인했으며, 10주차 AI 작업에 앞서 필요한 기본 기능 검증을 마쳤다. AI 기능 자체는 아직 구현하지 않았고, 10~12주차 작업은 이번 완료 범위에 포함되지 않는다.

## 2. 주요 변경 사항

| 항목 | 변경 및 확인 내용 |
|---|---|
| 검색 실패 안내 | 검색에 실패해도 보관함과 저장 자료로 바로 이동할 수 있도록 안내와 링크를 추가했다. |
| 저장 중 DB 잠금 처리 | 실제 SQLite 잠금이 발생하면 HTTP 503과 DATABASE_BUSY 응답을 보내고, 다른 저장 작업이 진행 중임을 알리도록 했다. 입력은 유지되며 잠금 해제 후 다시 저장할 수 있다. |
| 중복 검색 방지 | 검색 요청이 느린 상황에서 버튼을 두 번 눌러도 실제 검색 요청이 한 번만 전송되는 것을 확인했다. |
| 서버 재시작 후 복원 | 서버 프로세스를 실제 종료하고 같은 DB로 새 프로세스를 실행한 뒤 메모, 보관 상태, 보관함 상세와 통계가 유지되는 것을 확인했다. |
| 설치·운영 안내 | 새 폴더 준비, 설치, 실행, 종료, 재시작, DB 위치와 API 키 없이 사용하는 방법을 문서화했다. |

## 3. 테스트 결과

백엔드 자동 테스트 54건은 실패 0건, 오류 0건, 건너뜀 0건으로 통과했다. 기존 53건에 실제 DB 잠금 관련 테스트 1건이 추가되었다. 브라우저 검증은 9주차 7개 그룹과 기존 기능 회귀 검증 13개 그룹을 통과했다. 자동 테스트의 ‘건’과 브라우저 시나리오의 ‘그룹’은 다른 단위이므로 하나의 테스트 건수로 합산하지 않았다.

| 백엔드 자동 테스트 | 54건 통과 | 기존 기능, 데이터 검증, 전체 흐름, DB 잠금 등 |

실제 DB 잠금 시험에서는 별도 SQLite 연결로 쓰기 잠금을 건 뒤 메모 저장을 시도했다. 실패 안내가 나오면서 입력과 기존 DB 내용이 유지되었고, 잠금을 해제한 뒤 같은 입력을 저장할 수 있었다. 390px 폭의 모바일 화면에서도 가로 넘침이 없음을 확인했다.

검증 초기에 화면 정렬 순서와 API 기본 순위가 달라 다른 자료를 비교하는 시험 스크립트 오류가 있었다. 화면에서 실제 선택한 자료의 ID로 비교하도록 수정한 뒤 재검증했으며, 이 과정에서 사용자 데이터 손상은 없었다.

## 4. 설치 환경과 기존 기록 보존

Windows, JDK 25.0.1, Node 22.17.0, Edge headless 환경에서 검증했다. 소스를 작업 공간의 `output/week9-clean`에 복사하고 기존 빌드 결과, node_modules, 기존 DB와 .env 없이 설치와 실행을 확인했다. 다만 이 PC의 Maven/npm 캐시를 사용할 수 있는 환경이었으므로, 이는 **같은 PC의 새 폴더 검증이며 새 PC 전체 설치 검증은 아니다.**

검증용 서버는 18089, 웹 화면은 5179를 사용하고, 검증용 DB는 `output/week9-clean/runtime/research.db`에 따로 두었다. 합성 검색 모드와 AI 비활성화 상태로 시험했으며, **실제 외부 검색 API 추가 호출은 0회**였다.

기존 사용자 미리보기 DB는 SQLite 백업 기능으로 `output/week9-preview-backup.db`에 백업하고 무결성을 확인한 뒤 새 서버 파일을 연결했다. 전후 전체 행 비교에서 주제 2행, 자료 19행, 검색 실행 3행, 검색 결과 연결 19행, 자료·주제 연결 19행, 검색 예산 1행이 동일하게 보존되었다. 미리보기 DB의 읽기 상태와 메모는 원래 각각 0행이었으므로, 이 비교만으로 비어 있지 않은 메모 보존을 입증한 것은 아니다. 실제 내용이 있는 메모와 읽기 상태의 보존은 별도 통합·회귀 시험에서 확인했다.

사용자 미리보기는 5178 웹 화면과 18088 서버를 사용하며, DB는 `output/week7-preview.db`를 이어서 사용한다. **미리보기 DB는 원본 backend/data DB와 별개이며 기록이 원본에 자동 반영되지 않는다.** 원본 DB와 8080 서버는 이번 작업에서 수정하거나 종료하지 않았다.

## 5. 남은 한계

- 이번 검색 검증은 합성 결과를 사용했다. 실제 외부 검색의 새 호출 시험이나 AI 결과의 품질 검증은 수행하지 않았다.
- AI 요약과 구조화 출력은 아직 구현하지 않았다. 이번 완료 판정은 AI 없는 기본 기능에 한정한다.
- 연결 실패 시험은 브라우저 요청에 실패를 주입한 방식이며, PC 전체의 네트워크 장비 장애 시험은 아니다. 인터넷이 끊겨도 로컬 서버가 실행 중이면 저장 자료를 볼 수 있지만 새 실제 검색은 할 수 없다.
- 의존성 설치 검사에서 취약점 13건(중간 10건, 높음 3건)이 보고되었다. 이번 범위에서 강제 업데이트하지 않았으며, 설치·빌드 성공을 보안 검증 완료로 해석하지 않는다.
- 백업·복원 종합 검증, 성능 실측, 최종 보안 검증은 12주차 범위로 남아 있다.

## 6. 다음 10주차 계획

10주차(11월 16일~22일)에는 Ollama를 이용한 구조화 출력, 작업 대기열과 실패 복구를 구현할 예정이다. AI 요청이 실패하거나 지연되어도 이미 검증한 검색·보관·메모 기능을 계속 사용할 수 있도록 연결한다. 이후 11주차에는 근거 검사와 요약 화면을 진행하고, 12주차에는 백업·복원, 성능과 보안을 종합 점검할 계획이다.

## 7. 손으로 옮겨 적을 9주차 요약 5문장

1. 9주차에는 AI 없이 검색, 출처 확인, 보관, 메모, 읽음 표시와 통계까지 전체 이용 흐름을 점검했다.
2. 검색이 실패하면 보관함으로 이동할 수 있게 하고, 저장이 막혀도 작성 중인 메모를 유지하도록 개선했다.
3. 백엔드 자동 테스트 54건과 9주차 브라우저 검증 7개 그룹, 기존 기능 검증 13개 그룹을 통과했다.
4. 같은 PC의 새 폴더 설치와 실제 서버 재시작 후 기록 유지를 확인했으며, 미리보기 DB는 원본 DB와 별도로 사용한다.
5. 실제 외부 검색 API 추가 호출은 0회이고 AI는 아직 미구현이며, 10주차에는 AI 출력과 작업 대기열 및 실패 복구를 구현할 예정이다.

## 8. 1~5주차 쉬운 요약 5문장

1. 1주차에는 필요한 기능을 정리하고 사용자가 보게 될 화면과 이동 순서를 설계했다.
2. 2주차에는 자료를 저장할 데이터베이스와 화면에서 데이터를 주고받는 API를 만들었다.
3. 3주차에는 외부 검색 서비스와 연결해 관심 주제의 자료를 찾는 기능을 만들었다.
4. 4주차에는 검색한 자료에서 필요한 내용을 추출하고 자료를 분류하는 기능을 만들었다.
5. 5주차에는 같은 자료가 중복 저장되는 것을 줄이고 기존 검색과 자료 기록을 보존하도록 정리했다.
