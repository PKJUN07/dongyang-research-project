## 사용자 데이터 보존

개발 중 발견한 문제는 모두 최종 검증 전에 수정했다. 기존 인덱스와 마이그레이션 인덱스 이름 충돌을 새 이름으로 변경했고, fixture의 필수 updated_at을 보완했다. 프론트 문법·props 변경 lint 오류를 수정했으며 차트로 커진 단일 번들은 경로별 지연 로딩으로 분리했다.

기존 미리보기 `output/week7-preview.db`를 SQLite backup API로 `output/week8-preupgrade-backup.db`에 백업 후 버전6으로 마이그레이션했다. 기존 열 기준 전후 비교: 주제2, 문서19, 검색3, 검색결과19, 주제연결19, 읽기0, 메모0, 검색예산1 모두 동일. integrity_check=ok. 증거 `output/week8-preservation-result.json`.

기존 원본 `backend/data/research-board.db`와 8080 서버는 변경하지 않았다. 미리보기는 5178→18088이며 기존 preview DB의 연속 사용이다. 이 화면에서 입력한 기록은 preview에 남으며 원본으로 자동 복사되지 않는다.

## 직접 확인

1. http://127.0.0.1:5178/stats 에서 최근30일·전체주제로 조회한다.
2. 신규 자료19건(실제17+합성2), 검색3회가 나오는지 확인한다. 새로운 사용자 작업이 있으면 수치는 달라질 수 있다.
3. 신규 자료 숫자를 눌러 같은 기간의 목록을 열고 기간 기준이 ‘처음 저장일’인지 확인한다.
4. 자료 상세에서 읽음을 선택하고 통계로 돌아와 비율 변화를 확인한다. 보관하기 후 보관 건수를 눌러 해당 보관함을 확인한다.
5. 날짜별 수치 표와 그래프를 비교한다. 기타 출처도 포함됨을 확인한다.
6. 검색 이력의 ‘이 검색의 자료’ 링크를 열고 선택한 검색 결과만 나오는지 확인한다. 기존 작업의 raw/excluded는 미기록이다.
7. 자료가 없는 과거 기간은 0과 빈 상태 안내를 보여준다.

브라우저 자동화는 반드시 5177→18087의 격리 fake DB에서 실행한다. `RESEARCH_TEST_NODE_MODULES`에 Playwright 설치 경로, `RESEARCH_TEST_OUTPUT`에 증거 출력 경로를 지정한다. 사용자 미리보기5178을 자동화 쓰기 테스트 대상으로 지정하지 않는다.
