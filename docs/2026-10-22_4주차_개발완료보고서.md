## 완료 기준과 결과

제공된 단계별 개발 가이드의 4주차 통과 게이트는 두 키워드의 검색 결과·출처 분류·추출 성공 또는 실패 이유 기록, 발행일 미상과 수집일 구분, 본문 미확보 시 원문 링크 보존이다. 모든 사이트에서 본문을 수집하는 것은 목표가 아니며 허용 범위가 불명확하면 전문 저장을 보류하도록 되어 있다.

이 기준에 따라 실제 검색 결과 17건을 보존하고, 표본 5건의 운영 주체·글 성격·접근 조건을 검토하여 공식 2건·사용자 3건으로 분류했다. 확인하지 못한 나머지 12건은 기타로 유지했다. 본문 상태는 BLOCKED 1건, METADATA_ONLY 16건이며 실제 본문 저장 성공은 **0건**이다. 성공 추출 경로는 합성 HTML로 검증했다. 실제 본문 추출 성공률이나 자동 분류 정확도를 측정한 것으로 표현하지 않는다.

## 구현한 내용

PageFetcher·ContentExtractor·SourceClassifier를 DocumentService에서 연결하고 본문·상태·이유·분류 근거·확인 시각을 SQL 003으로 저장했다. 제목·검색 snippet·본문은 별도 필드이며 발행일 미상은 null, 수집하지 않은 본문의 fetchedAt도 null로 남는다.

URL 검사에서는 HTTP(S) 기본 포트만 허용하고 사설·루프백·링크로컬·예약 주소와 우회 경로를 거부한다. DNS의 모든 주소를 확인한 뒤 승인한 IP로 연결하며 리다이렉트마다 정책·주소를 다시 검사한다. 요청은 동시 1개, 도메인 간격 최소 1초, 리다이렉트 3회, HTML 1 MB, 추출 텍스트 100,000자로 제한한다. 전체 요청 15초 안에 DNS 대기는 최대 4초다. 로그인·유료벽·403을 우회하지 않는다.

Jsoup으로 script·style·메뉴·광고를 제외하고 article·main 본문 후보를 정리한다. 로그인 화면·JS 전용·짧은 오류 페이지는 정상 본문으로 저장하지 않으며, 파싱되지 않는 발행일은 생성하지 않는다. 추출 텍스트는 React에서 일반 텍스트로 렌더링한다.

정책에 등록한 정확한 호스트·경로, 운영 주체·근거 URL·검토일로 출처를 판정한다. 이번 검토 정책 5개는 전부 fetchAllowed=false다. 검토한 robots 금지 사유는 BLOCKED로, 저장 권한 미확인은 METADATA_ONLY로 전달한다. robots 허용만으로 저장·AI 입력을 허용한다고 해석하지 않았다.

기존 결과를 새 검색 없이 정정하는 ReprocessDocuments 도구를 추가했다. 사전 조회(--dry-run)와 명시적 반영(--apply)을 나누고, 기존 본문이 있으면 덮어쓰지 않는다. 실제 DB 백업 후 ID 1,7,8,14,17만 반영했다. 이번 적용에서는 본문 HTTP 요청을 하지 않았다.

## 검증 결과

- 전체 백엔드 자동 테스트 24건 통과. ContentSafetyTest 9건은 추출·분류·URL·리다이렉트·DNS 제한과 검토된 robots 거부의 무요청 처리를 확인했다.
- ReviewPersistenceTest 2건은 출처 정정 후 제목·요약·순위·링크·requestKey·호출 예산 보존과 기존 본문 덮어쓰기 방지를 확인했다.
- Maven package도 통과했으며 Spring Boot mainClass를 명시해 별도 CLI 진입점 추가 후에도 패키징되도록 했다.
- 실제 SQLite 온라인 백업과 반영 전후 대조 결과: topic·search_hit·검색 조건/요청키/시각·원본 문서·예산 지문이 모두 동일, integrity_check=ok, SERPER attempts=2.
- 실제 브라우저에서 작업 1은 PARTIAL·저장 7건·본문 제한 1건, 작업 2는 SUCCEEDED·저장 10건을 확인했다. 목록 새로고침, 공식 자료 상세 새로고침과 목록 왕복도 통과했다.
- 검색 요약만 제공되는 자료의 원문 링크 17건이 유지되며, 본문 미수집·발행일 미상·출처 근거가 구분되어 보인다.

현재 사용자가 실행 중인 서버를 종료하지 않았다. 기존 결과는 DB 반영 즉시 조회되지만 새 코드·정책의 서버 로딩은 다음 정상 재시작 시 적용된다. Start-ApprovedSearch.ps1은 별도 SOURCE_POLICY_PATH가 없을 때 이번 검토 정책을 선택한다. 일반 Maven 실행은 기본 빈 정책을 유지하므로 필요하면 환경변수로 정책 경로를 지정해야 한다.
