### 실제 검색 승인과 남은 검증

2026-10-16 사용자가 Serper 무료 크레딧으로 ‘애슐리 퀸즈’와 ‘클로드’ 각 1회, 합계 2회를 승인하고 서버를 준비했다. 에이전트가 키를 읽지 않고 로컬 서버의 SERPER·synthetic=false·UP 상태를 확인한 뒤 승인된 검색 2회를 완료했다.

애슐리 퀸즈 7건(작업1, 약3.32초), 클로드 10건(작업2, 약2.15초)이 SUCCEEDED로 저장됐다. 시간은 앱의 작업 접수·폴링·조회 전체 관측값이다. 17건의 제목·URL·검색 요약과 synthetic=false를 확인했다. 본문은 POLICY_NOT_APPROVED 사유로 METADATA_ONLY이고 출처는 OTHER다.

실제 결과 화면의 새로고침 복원, 계정 대시보드 크레딧 차감, 대상 사이트 운영 주체·정책·본문·분류 검증은 남아 있다. 추가 Serper 검색 대신 저장된 17건을 활용한다. 실제 기록은 backend/data/approved-search-smoke.json이다.

### 키 준비 후 실행

1. backend 폴더에서 `.\Start-ApprovedSearch.ps1`을 실행한다. 서버 환경변수에 키가 없으면 터미널의 가려진 입력창에 입력한다. 키는 파일에 쓰지 않는다.
2. 준비된 서버에 대해 `.\Invoke-ApprovedSearchSmoke.ps1`로 승인된 두 검색어를 실행한다. 기본 서버는 8080이며 다른 포트는 BaseUrl로 지정한다.
3. 스크립트는 요청 전에 requestKey를 로컬 영수증 파일에 기록한다. 재실행해도 같은 키로 기존 작업을 조회하며 검색 2회를 자동 추가하지 않는다. DB 누적 예산도 별도로 적용된다.
4. 결과 기록의 필드와 출처 후보, 대시보드 크레딧 차감을 확인한다. 개인 키·개인 DB·영수증을 Git 또는 외부에 업로드하지 않는다.
