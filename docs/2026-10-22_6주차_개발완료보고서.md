## 완료 기준과 결과

전체 저장 자료와 개별 검색 결과에 같은 필터 계약을 적용하고, 상세 화면을 확인한 뒤 목록으로 돌아와도 검색 조건이 유지되도록 구현했다. 제목 필터와 기간·출처 필터는 DB에 저장된 자료를 조회하는 기능이다. 필터 변경이나 페이지 이동으로 새 Google 검색 또는 Serper 호출을 실행하지 않는다.

`GET /api/documents`와 `GET /api/search-sessions/{id}/results`에 주제·출처·제목·기간 기준·시작일·종료일·정렬·페이지·페이지 크기·날짜 미상 포함 조건을 연결했다. 잘못된 값과 범위는 400으로 거부한다. 전체 목록은 최신 hit의 요약, 검색별 목록은 해당 검색 hit의 요약을 표시한다. 상세도 기본값은 최신 요약이며 `runId`가 있으면 그 검색의 요약을 사용한다.

## 구현한 내용

`DocumentsPage`, `DocumentsPanel`, `DocumentFilterBar`, `Pagination`을 연결했다. 필터와 페이지를 URL에 보관하고, 페이지 이외 조건을 변경하면 첫 페이지로 돌아간다. 상세 링크의 `returnTo`로 목록 조건을 복원한다. 조건을 queryKey에 포함하고 AbortSignal을 전달하여 이전 조건의 늦은 응답이 현재 결과를 덮어쓰지 않도록 했다.

정렬은 최근 검색 수집순, 발행일 최신순, 제목순, 검색 순위순을 제공한다. API 기본값은 기존 검색 호환을 위한 `RANK`이고 UI는 `FETCHED_DESC`를 명시한다. 허용된 정렬만 고정 SQL 조각으로 선택하고 같은 값에서는 문서 ID를 추가 정렬 키로 사용한다. 제목의 `%`와 `_`는 검색 패턴으로 확장하지 않고 문자 그대로 처리한다.

| 기간 기준 | 의미와 처리 |
|---|---|
| PUBLISHED | 원문에 표시된 발행 날짜를 사용한다. 알 수 없는 발행일을 임의로 만들지 않는다. |
| FETCHED | 본문 요청 시각 `fetched_at`이 아니라 검색 hit의 `retrieved_at`이다. 한국 시간의 날짜 경계로 조회한다. |
| 날짜 미상 | 기간 조건에서는 기본 제외한다. `includeUnknown=true`이면 날짜 미상 자료도 포함한다. 기간 조건이 없으면 이 옵션으로 미상 자료를 제외하지 않는다. |

상세 `ContentTabs`는 검색 제공자 요약과 공개 본문을 분리한다. 본문 미확보 상태와 이유, 본문 요청 시각, 발행일 미상, 도메인, 출처 분류 근거를 표시한다. 원문 링크에는 새 탭과 `noopener noreferrer` 속성을 적용했다. 검색 요약을 본문을 읽고 생성한 AI 분석으로 표시하지 않는다.

읽기 상태는 현재 `UNTRACKED`만 제공한다. API는 `ALL`·`UNTRACKED` 이외 읽기 조건을 거부한다. 읽음·보관·메모 작성 UI와 AI 분석은 미구현이며 화면에서도 후속 단계로 안내한다.

## 수동 브라우저 검증 결과

다음은 실제 브라우저 수동 조작 결과로, 자동 E2E 스위트와 구분한다. 검증용 화면과 지연 프록시는 업그레이드한 복사본 DB 서버에 연결했다.

1. 기존 검색 2의 결과 10건에서 공식 필터로 1건을 조회하고 상세 ID 8에서 본문 내용 화면으로 전환했다. 목록 복귀 후 공식 필터가 유지됐다. 원문 링크의 새 탭·보안 속성은 DOM에서 확인했으며 외부 원문 페이지를 새로 열지는 않았다.
2. 페이지 크기 5에서 1/2페이지와 2/2페이지 이동, 이전·다음 경계 비활성화, 출처 조건 변경 시 `page=0` 초기화를 확인했다.
3. 제목 ‘느림’의 응답을 프록시에서 2초 지연한 뒤 ‘Claude’로 바꾸었다. 최신 조건의 1건이 먼저 표시되고 이전 조건의 늦은 0건 응답은 취소되어 결과를 덮어쓰지 않았다. 이는 응답 순서 제어 시험이며 서비스 응답속도 측정값이 아니다.
4. 새로고침 후 검색 2·공식·제목 Claude·크기 5·첫 페이지와 결과 1건이 복원됐다. Tab과 방향키로 제목 입력에서 기간 기준으로 이동·변경하고 URL 반영을 확인했다.
5. 전체 저장 목록 17건을 확인하고 발행일 시작일 2026-10-02에서 0건, 날짜 미상 포함 선택에서 17건 복원을 확인했다.

별도 읽기 전용 API 확인에서도 전체 17건, 크기 5의 4페이지, 검색 2의 공식 1건, 발행일 10월 이후 조건 0건과 미상 포함 17건을 확인했다. 이번 신규 UI의 모바일·모든 브라우저·전체 접근성 감사·대규모 성능 측정은 수행하지 않았다. 이전 주차의 모바일 검증을 이번 검증으로 간주하지 않는다.

## 실제 자료와 운영 상태

기존 실제 검색 자료 17건의 복사본만 업그레이드·조회했다. 원본 서버와 원본 DB는 그대로 유지했다. 복사본의 무결성 검사는 `ok`이며 주제·검색 hit·검색 조건·원래 문서 정보·호출 예산의 보존을 확인했다. 원본에 대한 새 코드와 DB 변경은 다음 정상 서버 재시작 시 적용된다.

검색 1의 PARTIAL·7건·본문 제한 1건, 검색 2의 SUCCEEDED·10건, 공식 2건·사용자 3건·기타 12건을 유지했다. 본문 상태도 BLOCKED 1건·METADATA_ONLY 16건이며 실제 본문 확보 성공은 여전히 0건이다. 본문 파서와 중복 처리 시험은 합성 자료에 대한 검증이다. 이번 새 Serper 호출은 0회이고 누적 `attempts=2`를 유지했다.

주요 산출물은 `DocumentFilter.java`, `DocumentRepository.java`, 목록·상세 API, `DocumentsPage`·`DocumentsPanel`·`DocumentFilterBar`·`Pagination`·`ContentTabs`, `DocumentQueryTest`와 확장된 `WorkflowTest`이다. 5주차의 참조 메모 시험 테이블 보존은 사용자 메모 기능 완성이 아니다. 읽기·보관·메모 UI와 AI는 7주차 이후 구현 대상으로 남아 있다.

## 용지에 적을 요약

저장 자료의 주제·출처·제목·기간 필터, 정렬, 페이지 이동과 상세 화면을 구현했다. 발행일과 검색 수집일을 구분하고 날짜 미상 포함 옵션을 제공했으며, 상세에서 돌아오거나 새로고침해도 목록 조건이 유지되도록 했다. 자동시험 최종 38건과 타입·빌드·린트 검사를 통과했고, 실제 브라우저에서 필터·페이지·조건 복원·늦은 응답 취소를 확인했다. 기존 자료 17건의 복사본만 조회했으며 새 외부 검색과 실제 본문 추가 확보는 없었다.
