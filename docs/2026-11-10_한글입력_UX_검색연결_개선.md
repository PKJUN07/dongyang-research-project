## 수정

- 목록 제목 입력을 URL 값과 직접 결합하지 않고 로컬 draft로 관리한다. 입력 중에는 조회/이동을 하지 않으며 Enter 또는 ‘제목 검색’에서만 적용한다. IME 조합 중 Enter는 조회하지 않는다. 필터 초기화는 미제출 입력도 지운다.
- 메뉴 ‘저장 자료’→‘전체 수집 자료’, ‘읽기 보관함’→‘내 보관함’, 버튼 ‘보관하기’→‘내 보관함에 담기’.
- 실제 자료 목록에서 합성 자료를 기본 숨긴다. ‘테스트 자료 포함’으로 다시 볼 수 있다. 서버 synthetic 필터를 pagination 전에 적용한다. 검색 작업별 결과는 해당 작업의 자료를 계속 보여준다. 통계 KPI 링크는 합성 포함 여부를 명시하여 집계와 같은 문서 집합을 유지한다.
- 빈 보관함은 보관 방법과 자료 둘러보기 링크를 보여주고 0/0 페이지를 숨긴다.
- 요약 모음에 분석 완료/미분석/분석 중/재분석 필요/실패 상태를 표시한다. 준비되지 않은 자료를 선택하지 못하게 하고 상세 분석 후 모음으로 돌아올 수 있다.
- 검색 화면에 실제 검색/테스트 검색 구분, 준비되지 않은 이유, 누적 사용/상한/남은 요청 수 표시. fake 버튼은 ‘테스트 검색 (외부 호출 없음)’으로 표시한다.

## 외부 검색 진단과 승인

Serper 구현은 존재하고 과거2회 실제 호출로17개 자료를 수집했다. 현재 미리보기는 fake 모드여서 신규 실제 검색이 수행되지 않았다. 진단 당시 프로세스·사용자 환경변수에 키가 없었고 원본8080 서버도 실행되지 않았다. 키 값은 출력하지 않았다.

사용자가 추가5회를 승인하여 기존 사용2를 보존하고 누적 상한7로 설정했다. 하루 제한이 아니며 날짜가 바뀌어도 자동 초기화되지 않는다. 실패한 실제 요청도 예산을 사용한다. Serper 계정의 크레딧과 앱의 승인 상한은 별개다.

키는 로컬 `tools/Connect-ResearchBoard-Serper.ps1` 입력 도구에서 AsSecureString으로 입력받고 서버 환경변수로만 전달한다. 파일·채팅에 키를 기록하지 않는다. 키 입력 후 serper/승인true/누적7로 기존 preview DB를 이어 사용한다. 이 도구 자체는 실제 검색을 호출하지 않는다. 준비 상태 확인은 제공자의 인증 성공 검증과 다르며 첫 실제 요청으로 확인한다.

현재 작업 종료 직전까지 키 입력 완료 증거가 없으면 실제 검색은 ‘연결 대기’로 남긴다. 연결 완료라고 추정하지 않는다.

추가 완료 결과: 사용자가 로컬 창에서 키를 입력했고 SERPER/READY로 전환됨을 확인했다. 추가 승인5회 중1회로 ‘클로드’ 검색(run4)을 실제 호출했다. SUCCEEDED, synthetic=false, 발견10/저장10/실패0, errorCode=null. 현재 누적3/7·남은4회. 실제 검색 응답과 저장까지 검증 완료. 원문 본문 수집 정책은 비어 있으므로 새 페이지 본문을 자동 요청하지 않고 검색 요약·원문 링크를 저장했다. 키는 서버 환경변수에만 있으며 파일/채팅에 기록하지 않았다.

실제 호출 증거: 작업 공간 output/2026-11-10-serper-verification.json, output/ux-ime/chrome-serper-success.png. 기존19건은 유지되고 이번 검색의 새로운 문서4건이 추가되었다. 위의 ‘실제 외부 추가 호출 없음’은 실제 스모크 전 개발·자동 테스트 범위만 의미하며 이번 작업 전체의 실제 추가 호출은1회다.
