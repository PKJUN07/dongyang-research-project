## 개발 목표와 결과

관심 주제를 생성하고 SQLite에 저장한 뒤 화면에서 다시 조회할 수 있도록 구현했다. 합성 검색 요청을 작업으로 접수하고, 검색 결과를 DB에 저장해 목록과 상세 화면에 연결했다. 서버 재시작 후에도 주제와 검색 결과가 유지되는 것을 확인했다.

이 보고서는 2주차의 로컬 저장과 합성 검색 흐름을 다룬다. 실제 검색 제공자 호출과 공개 웹페이지 검증은 후속 주차에 별도로 판정한다.

## 수행한 개발

### 데이터베이스 기반

SQLite 파일 연결과 SQL 마이그레이션을 구성했다. 초기 스키마에는 topic, search_run, document, search_hit 테이블을 만들었다. 검색 실행마다 달라지는 순위와 검색 요약을 문서 자체 정보와 분리해 저장했다.

각 연결에서 외래키 검사와 busy timeout을 설정하고 WAL을 적용했다. 쓰기 작업은 트랜잭션으로 처리하며 오류 시 롤백하도록 했다. schema_version에는 마이그레이션 적용 성공 후 버전을 기록한다. 사용자 입력은 SQL 파라미터로 바인딩한다.

### API와 검색 작업

주제 생성·목록 조회, 검색 작업 접수·상태 조회·결과 조회, 자료 상세 API를 구현했다. 검색 접수는 HTTP 202와 작업 ID를 반환하며, 별도의 제한된 실행기가 합성 검색과 저장을 수행한다. 입력값의 공백·길이·주제 존재 여부를 검사한다.

같은 요청 키를 다시 보내면 기존 작업을 반환하고, 실행 중인 동일 검색은 병합하도록 했다. 서버가 재시작되면 중단된 대기·실행 작업을 INTERRUPTED 실패로 정리하여 성공으로 오인하거나 외부 요청을 자동 반복하지 않게 했다.

### 화면 연결

React에 주제 생성·선택과 검색 폼을 연결했다. 검색 작업이 끝나면 저장된 결과 카드를 표시하며, URL의 runId로 결과를 다시 조회한다. 카드에서 상세 화면으로 이동하고, 새로고침 후에도 자료를 확인할 수 있도록 했다. 제목·URL·검색 요약과 합성 자료 표시를 제공한다.
