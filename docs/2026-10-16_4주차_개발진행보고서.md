## 개발 목표와 현재 결과

검색된 자료의 허용된 공개 본문을 추출하고, 공식·사용자·기타 출처와 판단 근거를 표시하는 기능을 구현했다. 한 페이지의 본문 처리 실패가 전체 검색 링크를 없애지 않도록 검색 요약과 본문, 검색 성공과 추출 상태를 구분했다.

본문·분류 모듈 검증에는 합성 HTML과 테스트 정책을 사용했다. 이후 실제 검색 결과 17건을 확보했으며, 모든 자료는 정책 미승인 사유로 METADATA_ONLY와 OTHER 상태를 유지했다. 대상 사이트의 운영 주체·접근 조건 검토와 실사이트 추출·분류 판정은 남아 있다.

## 수행한 개발

### 안전한 페이지 요청

PageFetcher가 요청 전에 SourcePolicy와 UrlSafety를 확인하도록 했다. 정확한 호스트·경로와 검토 근거가 등록되고 본문 요청이 허용된 페이지만 접근한다. 정책이 없는 자료는 원문 링크와 검색 요약을 유지하고 METADATA_ONLY로 처리한다.

HTTP(S) 기본 포트만 허용하고 사설·루프백·링크로컬·예약 주소, 인증정보가 포함된 URL과 일부 경로 인코딩 우회를 차단했다. DNS의 모든 주소를 검사한 뒤 확인된 IP를 연결에 고정한다. 리다이렉트는 자동으로 따르지 않고 목적지 정책과 주소를 다시 검사한다.

동시 요청 1개, 도메인별 간격 최소 1초, 최대 리다이렉트 3회, 응답 1 MB, 추출 텍스트 100,000자 상한을 적용했다. 페이지 요청은 15초 예산을 사용하며 DNS 대기는 그 안에서 최대 4초로 제한했다. 로그인·403·유료벽은 우회하지 않는다.

### 본문과 메타데이터 추출

Jsoup으로 HTML을 분석하고 script·style·메뉴·광고 등을 제거한 뒤 article 또는 main에서 본문 후보를 추출했다. 문자 인코딩과 공백을 정리하고 발행일·canonical URL 후보를 별도 처리한다. 발행일이 없거나 파싱되지 않으면 null로 남기며 수집 시각으로 대체하지 않는다.

본문과 검색 요약을 별도 필드에 저장했다. 상태는 SUCCESS, METADATA_ONLY, BLOCKED, FAILED로 구분한다. 로그인 화면과 본문이 없는 JS 전용 페이지는 본문 확인 성공으로 처리하지 않는다. 이 방식이 모든 사이트의 로그인·유료벽 또는 본문 구조를 판별한다고 보장하지는 않는다.

### 출처 분류와 저장

SourceClassifier는 검토한 호스트·경로·운영 주체·근거 URL·검토일을 사용한다. 도메인 이름이 비슷하거나 검색 순위가 높다는 이유로 공식 출처로 분류하지 않는다. 판단 근거가 없으면 OTHER로 유지한다.

세 번째 SQL 마이그레이션으로 본문, 추출 상태·이유, 본문 해시, 수집·분류 시각과 canonical 후보를 저장할 열을 추가했다. DocumentService가 요청·추출·분류를 조합하고 검색 Worker와 연결한다.

### 실패 처리와 화면

본문 실패가 있어도 검색 결과 링크와 검색 요약을 저장한다. 작업 상태에는 PARTIAL을 사용하고 실패 수를 표시한다. 카드와 상세 화면에는 출처 근거, 발행일 미상, 본문 확보 여부와 실패 이유를 표시한다. 본문은 React 텍스트로 렌더링하여 HTML 스크립트를 실행하지 않는다.

## 남은 완료 조건

1. 3주차에서 실제 두 키워드 검색 결과 17건을 확보했다. 추가 유료·무료 검색을 호출하지 않고 저장된 결과로 후속 검증한다.
2. 소수의 대상 페이지에 대해 운영 주체, robots.txt, 이용 조건과 본문 저장·처리 허용 범위를 확인한다.
3. 확인한 근거와 경로를 정책에 기록하고 허용된 페이지에만 요청한다.
4. 각 자료에 결과 링크, 출처 유형과 근거, 추출 성공 또는 실패 이유를 기록한다. 본문 미확보 자료도 링크를 유지한다.
5. 발행일 미상과 수집 시각을 구분하고 원문과 추출 텍스트를 비교한 뒤 완료 보고서로 갱신한다.

공개적으로 열리는 페이지라는 사실만으로 본문 저장이나 AI 입력이 허용됐다고 판단하지 않는다. 기본 정책 파일은 비어 있으며 예제 JSON은 실제 허용 목록이 아니다.
